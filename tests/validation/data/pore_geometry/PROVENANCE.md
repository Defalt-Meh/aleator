# Source

## Crystal structures: `LTA.cif`, `MFI.cif`, `FAU.cif`, `PTY.cif`

Fetched live during this milestone (2026-08) from the IZA-SC Database of
Zeolite Structures, all-silica DLS76-optimized coordinates:

- `http://europe.iza-structure.org/IZA-SC/cif/LTA.cif`
- `http://europe.iza-structure.org/IZA-SC/cif/MFI.cif`
- `http://europe.iza-structure.org/IZA-SC/cif/FAU.cif`
- `http://europe.iza-structure.org/IZA-SC/cif/PTY.cif`

`LTA.cif` and `PTY.cif` are byte-identical to the CIF text already embedded
as `kLtaCif`/`kPtyCif` in `tests/validation/test_cif_real_structures.cc`
(same IZA source, confirmed by direct comparison) — that suite already
proves this codebase's CIF reader (symmetry expansion, triclinic cells)
against these two structures. `MFI.cif` and `FAU.cif` are new to this
milestone.

- LTA: cubic, `Pm-3m` (#221), a = 11.9190 Å, 72 atoms after symmetry
  expansion (48 symmetry operations).
- MFI: orthorhombic, `Pnma` (#62), a=20.0900 b=19.7380 c=13.1420 Å, 288
  atoms after expansion.
- FAU: cubic, `Fd-3m` (#227), a = 24.3450 Å, 576 atoms after expansion.
- PTY: **triclinic**, `P-1` (#2), a=7.1158 b=9.1748 c=9.1160 Å,
  alpha=84.645 beta=83.816 gamma=86.659 degrees, 30 atoms after expansion
  — the invariant-6 case (non-orthogonal cell, off-diagonal lattice
  matrix entries all nonzero).

All four are pure SiO2 (T-site = Si, no extra-framework cations), matching
the radii this codebase's `zeoPlusPlusDefaultRadiusAngstrom("Si"|"O")`
already provides.

## Reference LCD / PLD / ASA / AV: real Zeo++ 0.4.7 output on these exact files

Reference numbers were generated by installing and running the real,
actively-maintained Zeo++ fork (`zeopp-lsmo`, lsmo-epfl) via
`mamba create -n zeopp -c conda-forge zeopp-lsmo`, then running its
`network` executable directly on the four CIF files above — not
transcribed from a paper table, so the comparison is exactly reproducible
against the same input files checked into this directory.

```
network -res <name>.cif                       # LCD, PLD (both "diameter of the largest included sphere" convention -- second column is PLD)
network -sa  1.86 1.86 2000  <name>.sa <name>.cif   # accessible/non-accessible surface area, N2 probe
network -vol 1.86 1.86 50000 <name>.vol <name>.cif  # accessible/non-accessible volume, N2 probe
```

Zeo++ uses its own default radii (`networkinfo.cc`, `initializeRadTable()`,
"Parameters taken from CCDC tables") — O=1.52, Si=2.10 Å, the same values
`zeoPlusPlusDefaultRadiusAngstrom` in this codebase returns (traced to the
same live source, see `pore_analysis.cc`).

## Why LCD (all four structures) and PLD/ASA/AV (PTY only) are known deviations

This codebase's own Voronoi network is built on Voro++'s
`container_periodic_poly`, which computes the **power (Laguerre) diagram**
for a set of differently-sized spheres — partitioning space by
`|p-c|^2 - r^2`. Zeo++ uses the same underlying approach (see its own
`network.cc`) but the diagram most people mean by "Voronoi decomposition of
unequal spheres" is technically the **Apollonius (additively-weighted)
diagram** (`|p-c| - r`), which has curved (hyperbolic) cell boundaries and
is not what any fast library, including Voro++, actually computes.

- **LCD** (largest cavity diameter) is a single global maximum over free
  radii, and this codebase's own numbers sit systematically **1-4% below**
  the real Zeo++ numbers above (LTA 3.6%, MFI 1.0%, FAU 1.3%) on all three
  orthogonal structures, and further below on PTY. This was checked, not
  assumed: also tracking the maximum free radius seen while sampling edge
  interiors (already being computed for PLD) never exceeded the
  vertex-only maximum for LTA -- ruling out "missed candidate point on an
  edge" as the explanation *there*. The remaining, most likely explanation
  is a genuine algorithmic difference between the two tools' exact
  power-diagram implementations (grid/wall handling, vertex merging
  tolerance, or the constrained "point radical center" search Zeo++'s own
  paper describes using in addition to raw Voronoi vertices) -- not
  independently confirmed further within this milestone.

- **PLD** (pore limiting diameter) is a percolation-threshold computation
  over a graph of Voronoi-vertex/edge free-radii. On LTA, MFI, and FAU it
  empirically agrees with real Zeo++ to within 4e-4 Å once edge-interior
  constrictions are sampled finely enough (see `voronoi_network.cc`'s
  `kEdgeSampleSpacingAngstrom`), and is validated TIGHT (1e-3 Å) against
  those three in `tests/validation/test_pore_geometry.cc`.

  **PTY is different, and was investigated directly rather than assumed to
  be more of the same LCD-style noise.** Its PLD comes out 3.85082 Å vs.
  Zeo++'s 3.92186 Å (0.071 Å gap -- ~180x every LTA/MFI/FAU gap). Four
  independent checks were run before accepting this as a real, explained
  deviation rather than a bug:
  1. This codebase's CIF-derived lattice matrix for PTY, converted through
     the same Gram-Schmidt canonicalization `voronoi_network.cc` uses, was
     compared directly against Zeo++'s own printed box vectors
     (`va=(7.115800 0 0) vb=(0.534693 9.159206 0)
     vc=(0.981991 0.794885 9.028029)`) -- exact match to 6 decimal places.
  2. `Lattice::minimumImageDisplacement` on this exact triclinic cell was
     cross-checked against a brute-force image search (-3..3 in each
     lattice direction) over 200,000 random point pairs: zero mismatches,
     max relative error 1.5e-14 (floating-point noise). This is now a
     standing test (`tests/validation/test_pore_geometry.cc`, tagged
     `[invariant6]`) -- the codebase's own triclinic PBC primitive is
     independently proven correct on this cell, not just assumed from
     other milestones' coverage.
  3. Voro++'s grid resolution (`perAxis`, 1 for PTY's 30 atoms under the
     `n/4` sizing heuristic) was forced to 4 and re-run: bit-identical
     output (236 nodes, 2832 edges, same LCD/PLD to the last printed
     digit) -- ruling out grid coarseness as the cause, confirming
     `compute_cell()`'s own documented grid-independence.
  4. The sum of all 30 Voronoi cell volumes was checked against the total
     domain volume: 588.402505 = 588.402505 (diff ~2e-13) -- Voro++'s
     tessellation for this cell is exact and complete, matching Zeo++'s
     own printed "Volume check" line exactly.

  With the geometry primitives all independently confirmed correct, the
  percolation-critical edge itself was inspected directly: the edge that
  sets this codebase's PLD connects two Voronoi vertices of radius 1.97537
  and 1.97491 Å, but this codebase's interior-of-edge sampling (the same
  machinery validated on LTA) finds a real constriction of radius 1.92541
  Å partway along that edge's physical path -- *below both endpoints*.
  Zeo++'s reported threshold, 1.96093 Å, is suspicious in a specific way:
  it is *exactly* the free radius of one of this codebase's own Voronoi
  vertices (node 59, r=1.96093). That is consistent with Zeo++'s
  percolation graph treating vertex radii as the binding constraint and
  not fully accounting for this specific interior-of-edge constriction --
  i.e. a real methodological difference in what counts as "the network"
  between the two tools, not a bug in either. This exact edge-interior
  effect is what the LTA investigation (see `known_deviation_baseline.md`)
  already established matters for percolation; PTY is simply the first
  structure tested here where it moves the final answer measurably. Not
  independently confirmed against Zeo++'s own source in this milestone
  (Zeo++ was used as a live, run reference tool, not read as source here)
  -- the vertex-radius coincidence is strong circumstantial evidence, not
  proof.

  Because PLD's gap on PTY has a different, PTY-specific cause than
  LTA/MFI/FAU's near-exact agreement, and because ASA/AV are computed from
  the same percolation classification, PTY's PLD *and* ASA/AV are treated
  as known deviations (`known_deviation_baseline.md`) rather than folded
  into the tight LTA/MFI/FAU test at a loosened tolerance -- CLAUDE.md
  section 4: never widen a tolerance to swallow a disagreement that hasn't
  been individually explained.
